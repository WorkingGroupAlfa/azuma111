# Админка меню AZUMA (`/admin`)

Меню и статистика хранятся в **Upstash Redis** (Vercel Storage, бесплатный тариф). Сохранение в админке сразу
меняет меню в базе; сайт получает его через `/api/data` (кеш на CDN ~30 секунд). GitHub и пересборка не нужны.
Если база пуста или недоступна, сайт показывает меню из файла `js/data.js`, который лежит в репозитории.

## Файлы
- `admin/index.html`, `admin/admin.css`, `admin/admin.js` — панель: меню, история изменений (`#history`), статистика (`#stats`).
- `api/*.js` — функции Vercel (Node 18+, без зависимостей): `login`, `menu`, `history`, `rollback`, `data`, `track`, `stats`; общий код в `api/_lib/`.
- `js/data-fallback.js` — если `/api/data` не загрузился (нет сети при первом визите, сайт открыт как файл), подгружает `js/data.js`.
- `js/track.js` — анонимные счётчики посещений.
- `vercel.json` — подключает `js/data.js` к функциям (`includeFiles`) и задаёт заголовки (CSP для админки и т. п.).
- `admin/dev-server.mjs` — локальный стенд (в деплой не попадает, см. `.vercelignore`).

## Настройка (один раз, в существующем проекте Vercel)
1. Vercel → проект сайта → **Storage** → **Create Database** → **Upstash for Redis** (Marketplace) → тариф **Free** → регион рядом (например, Frankfurt) → **Connect to Project** (этот проект, все окружения).
   Переменные `KV_REST_API_URL` и `KV_REST_API_TOKEN` (или `UPSTASH_REDIS_REST_URL` / `UPSTASH_REDIS_REST_TOKEN`) добавятся сами.
2. Settings → **Environment Variables** → добавить:
   - `ADMIN_PASSWORD` — пароль владельца (длинный, 12+ символов);
   - `SESSION_SECRET` — необязательно: случайная строка 32+ символа (без неё ключ подписи выводится из пароля).
3. **Deployments → … → Redeploy** (переменные применяются только к новому деплою).
4. Открыть `https://<домен>/admin`, ввести пароль. Первое сохранение в админке копирует меню из `js/data.js` в базу; дальше сайт берёт меню из базы.

**Сменить пароль:** изменить `ADMIN_PASSWORD` → Redeploy. Все открытые сессии станут недействительны (если задан `SESSION_SECRET` — смените и его).

## История и откат
Перед каждым сохранением предыдущее меню попадает в историю (последние 20 версий). В админке: «Історія змін» → «Повернути цю версію».
Откат тоже сохраняется как новая версия, его можно отменить.

## Если разработчик меняет `js/data.js`
После того как владелец что-то сохранил, сайт показывает меню **из базы**, а не из файла. Если разработчик потом обновит `js/data.js`
(фото, новые блюда), админка покажет «Розробник оновив файл меню…», и владелец сможет заменить версию из базы версией из файла
(текущая уйдёт в историю). Чтобы не потерять правки владельца, разработчику лучше сначала скачать актуальное меню:
«Історія змін» → «Скачати data.js», и вносить изменения в этот файл.

## Локальная проверка (без Vercel и Redis)
```
ADMIN_PASSWORD=test node admin/dev-server.mjs 8787
```
Сайт — http://localhost:8787/, админка — http://localhost:8787/admin/. Вместо Redis используется JSON-файл
(`LOCAL_REDIS_FILE`, по умолчанию во временной папке ОС); `js/data.js` только читается.
`LOCAL_REDIS_FILE` и `BUNDLED_DATA_FILE` — только для локальных тестов, в Vercel их не задавать.
